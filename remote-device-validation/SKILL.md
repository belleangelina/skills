# 远程设备验证

## 核心原则

使用这个 skill 时，远程验证必须可复现、可回滚、可解释。流程可以沉淀到 skill，具体设备输入不能沉淀到 skill。

## 复用设备信息

复用当前会话已明确的目标设备、访问方式和授权，不重复向用户确认。部署、重启、网络调整或其他状态变更前，仍须读取已有的用户指定输入文件；未指定时检查并读取默认文件，以合并设备限制和恢复条件：

```text
docs/remote-device-validation-inputs.md
```

输入文件不存在但会话已有本轮所需信息时可继续。会话中的一般操作请求不视为取消文件中的具体限制；有冲突且用户未明确覆盖时，先澄清冲突。已读取且无变化迹象的同一文件无需逐条命令重读。仅当本轮操作依赖的信息缺失、冲突或有证据表明过期时询问，不重复确认已明确的信息。只读日志检查只需相应访问条件，不要求补齐 OTA 或恢复清单；部署、重启和网络变更再检查相关覆盖范围与恢复路径。不要把具体 IP、账号、密码、测试数据复制到 skill 或 skill references。

执行远程自循环验证前，必须读取 skill 内的泛化参考；只做轻量规划或创建输入模板时可只读相关部分：

## 执行流程

按任务范围选用以下步骤；只读检查不执行部署与状态变更步骤。

1. 按上述规则复用会话信息，并在状态变更前读取已有输入文件、合并约束；执行远程自循环验证前读取 `references/remote-device-validation-guide.md` 和相关功能专项文档。
2. 按本轮动作检查访问方式、升级覆盖范围和恢复条件。用户已要求设备部署或远程自循环验证时，继续执行其范围内必要的 OTA、SSH 临时替换、重启、临时网络调整和本轮测试数据清理，遵守已有约定与限制，不逐项重复询问。仅规划或读取日志的请求不自动授权部署、重启或网络变更；技能本身不扩展任务授权。
3. 改动前建立板端基线：版本、进程、网络、路由、DNS、目标配置、目标文件校验值和聚焦日志。
4. 按改动范围选择部署方式：
   - `/opt/aio` 或 `/opt` Web 资源：最终验证优先使用项目应用轻量升级包加设备重启，具体包名以输入清单为准。
   - `/usr/lib`、`/usr/bin`、`/etc` 或 rootfs 文件：先确认升级包覆盖范围；SSH 替换只作为探测。
   - 内核、DTS、驱动、bootfs 或分区：使用对应系统升级包或完整烧录路径。
5. 部署后等待设备恢复，再复查远程访问和关键状态。
6. 复现原问题或目标流程，再跑核心回归。
7. 做验证收尾：恢复临时网络/路由/DNS/挂载状态，停止临时后台命令，清理敏感临时文件。
8. 记录每轮目标、部署方式、构建产物、设备状态、关键命令、关键输出、结论和下一步。

## 输出控制

不要把完整构建日志、完整 `logcat`、完整 `dmesg` 或大量远端输出写进对话。大输出重定向到 `/tmp/*.log`，对话只保留真实退出码、关键错误、相关片段和必要尾部日志。

如果 SSH 返回码为 0 但 stdout 为空，不要直接判断远端命令没执行。把 SSH stdout/stderr 和必要的 `-vv` 日志写到 `/tmp`，检查认证、命令发送、退出状态和重定向后的 stdout 文件。

SSH 远程命令要尽量短、分步执行。不要把停止服务、复制文件、改权限、同步、启动服务、等待、读取状态和 remount 打包成一条长命令。启动脚本或后台进程可能继承 SSH 会话输出，导致动作完成但连接不退出；遇到这种情况，先中断该 SSH，再用新的短命令读取部署结果和进程状态。

## 部署规则

**任务包含应用部署与最终板端验证时，优先使用项目 APP 轻量升级包加重启，确认 OTA 解包、启动脚本、环境变量和 `/opt` 资源整体状态。**

SSH 临时替换只适合快速定位，前提是用户授权且文件系统状态明确。涉及 `aio` 的改动，单纯替换 `/opt/aio` 并只重启进程，不能作为最终验证结论，除非用户明确接受这个范围。

SSH 替换文件时：

- 先确认根文件系统读写状态。
- 只备份本轮验证需要替换的文件。
- 重启进程或设备前执行 `sync`。
- 验证新进程实际加载了目标文件，例如共享库用 `/proc/<pid>/maps`。

## 常见错误

- 缺少本轮动作必需的设备信息仍执行操作，或重复索要已明确的信息。
- 将只读检查扩展为未经任务授权的部署、重启或网络修改。
- 把设备 IP、密码或项目测试数据写入 skill。
- 用应用轻量升级包验证其覆盖范围之外的文件。
- 把 SSH 临时替换结果当作 OTA 成功证据。
- 把一整轮部署和检查写成一条很长的 SSH 命令。
- 忽略路由和 DNS 变化，导致远程访问被切断。
- SSH、curl、scp 或 OTA 被工具环境限制后继续尝试绕过。
