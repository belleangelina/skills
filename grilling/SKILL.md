# Grilling

澄清需求和实现方案，直到双方达成共识，然后再正式开工。任务复杂本身不构成增加追问的理由。

## 规则

- 找出尚未确定的关键事项及其依赖关系，优先解决会影响后续判断、整体方案或实现结果的上游决策。依赖尚未确定答案的问题，留到前提明确后再问。
- 能够自行查明的问题，优先探索现有上下文、代码库和相关资料，仍缺少必要信息时可自行判断是否需要联网搜索并执行，最后再询问用户。
- 只问关键问题，用尽可能少的问题达成共识。不要过分追问次要细节，除非用户明确要求讨论。
- 默认每轮只问一个问题，少量互不依赖的问题可以在同一轮提问。存在合理选项时给出推荐及理由，依据不足时明确说明。
- 同一轮有多个问题时，从“问题 1”开始编号。有备选答案时，每题选项从 A 开始编号。
- 每轮收到回答后，更新已确定的决策和待澄清事项，删除不再适用的分支，再询问前提已明确的关键问题。
- 当关键决策已经明确，或用户要求停止追问时，整理方案，简要说明哪些事项由 Agent 自行决定，提交方案并让用户审核。简单需求在对话中输出方案，复杂需求编写设计文档，文档位置遵循项目约定，无约定时使用 `docs/spec/`，已有相关文档则优先更新。
